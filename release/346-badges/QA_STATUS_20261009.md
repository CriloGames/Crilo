## Tests executed this session

1. Positive and negative live database requirement checks: **68/68 positive and 68/68 negative passed** for previously installed wheel/number/score badges.
2. Replayed **1,000 valid randomized Daily runs** through two distinct PostgreSQL rule evaluators, covering **215,000 paired award decisions**, with **zero disagreements**. Randomized generator follows the 12 original sectors, special spin refunds, +2-spin net gain, and Upgrade number-sector additions.
3. The production award/refresher path was tested inside SQL transactions rolled back after each test, with new-definition insertion, several named award assertions, Test Run isolation, and delete provenance checks. Test changes did not persist.
4. On isolated 1,000-period synthetic account histories, the account rule checks succeeded for all **53 lifetime**, **15 consecutive-day**, **15 leaderboard**, **8 drawing**, and **30 exploration** rules. At least six of ten social rules were demonstrated in database fixtures; high friend-count milestones were not injected into the actual production schema because fictitious friendship endpoints fail real foreign-key constraints. Existing offline positive/negative mock checks cover those thresholds, but they are not equivalent to authenticated social E2E tests.
5. Compared the 30 exploration badge event keys against live JavaScript sources; all 30 have matching tracking points in site code.
6. Compared all seven badge accent hex values against the seven colors in the game Info rarity legend; the hex codes match exactly. CSS suppresses icons inside badge tiles.
7. Audited existing awards against the live V3 predicates: **189 total**, 132 run-linked and 57 account-linked; no live predicate mismatches or links to Test Runs were found.
8. A stricter current-wheel replay audit identified **30 awards associated with two older/incompatible recorded runs**: one with no stored spin results (one award), and another with an earlier 11-sector wheel (29 awards). Those are *not proof of fraud*, but their provenance cannot be certified using the current 12-sector evaluator. We preserved them for owner review rather than deleting historical awards unilaterally.
9. Secured the event RPC to authenticated users only; removed direct guest/client grants on V3 staging/events tables and execution on internal V3 trigger and finalization functions. The browser's now-inaccessible finalization call was removed and frontend script cache revisions bumped.
10. Added and verified a secured nightly Supabase `pg_cron` job for V3 leaderboard settlement at **22:02 UTC**, immediately after the existing 22:01 UTC rank refresh.

## Outstanding conditions for a defensible 100% production certificate

**Not yet passed:** A live authenticated browser-to-Supabase user journey for each rule family (including sign-in, actual wheel outcome, saved run, gallery appearance, unlocked/locked rarity tint, friend actions, domain interactions, and owner deletion). This execution environment lacks an authenticated Crilo browser session. Static instrumentations and SQL rollbacks do not prove that all clickable controls fire in a real browser.

**Not mathematically measurable from 1-player simulations:** leaderboards (depends on user population and score competition), social achievements (friends and retention), exploration (behavioral events), and multi-month streak retention. These have testable trigger conditions rather than a defensible single-roll percentage.

**Historical exception:** The two legacy run formats behind 30 existing awards require an owner policy decision on grandfathering. They were not silently deleted.

**Conclusion:** The full 346 definitions are active and the server logic passes the automated checks listed above, but **not all 346 are production-certified end to end**. Status is **DEPLOYED — browser smoke testing / legacy reconciliation pending**. Do not advertise an unconditional 100% guarantee yet.
